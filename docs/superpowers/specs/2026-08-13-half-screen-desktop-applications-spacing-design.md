# 电脑半屏与桌面申请列表排版设计

## 目标

修复中英文界面在电脑半屏下的申请列表列宽失衡，以及 `821px` 附近从紧凑布局突然切换为 `1040px` 桌面表格而产生的裁切；同时优化电脑版申请列表的左右间距。

用户已选择视觉方案 **B：舒展两行**。

## 范围

本轮只调整申请列表的响应式排版与左右间距：

- `521px–1024px`：使用舒展两行记录布局。
- `1025px` 及以上：使用九列桌面表格，并优化容器和表格的左右间距。
- `520px` 及以下：保持现有手机五列布局不变。
- 首页、登录页、申请表单、数据结构、保存逻辑、筛选、排序、分组、A–Z 索引、编辑、删除、导入和导出功能均不改变。

## 根因

当前 `max-width: 820px` 的紧凑五列布局给身份列和操作列分配较多宽度，英文 `Candidate Home` 在 `670px` 半屏中仅约 `78px`，产生过度换行。到 `821px` 时页面立即切换为最小宽度 `1040px` 的九列表格，而主工作区不足以容纳它，造成视觉裁切和明显的横向滚动。

## 半屏布局：521px–1024px

申请记录采用连续白色列表，每条记录分成两行：

1. 第一行保留四个信息区：
   - 公司 / 岗位；
   - 申请日期；
   - 当前状态；
   - 候选人中心。
2. 第二行只放操作区，编辑和删除按钮靠右并排。
3. 表头只对应第一行四个信息区；“操作”不在狭窄表头中单独占列。
4. 公司与岗位仍是同一身份区的上下层级。
5. 英文长标题与日期可以自然换行，但不得侵入其他列。
6. 编辑和删除必须保持独立、清楚、可点击的按钮区域。
7. A–Z 索引继续固定在右侧，不覆盖记录或按钮。

`821px–1024px` 不再使用九列桌面表格，避免断点突变。

## 桌面布局：1025px 及以上

1. 保留现有九列信息和表格语义。
2. 申请列表面板在可用工作区内充分展开。
3. 工作区、申请视图、面板和表格的左右间距使用一致节奏，避免左侧层层叠加留白或右侧给 A–Z 索引预留过多空间。
4. 申请视图仅预留 A–Z 索引实际需要的安全距离。
5. 在 `1200px` 常见电脑宽度下，九列优先利用可用宽度；若长内容仍需横向滚动，滚动必须局限在表格容器内，页面本身不得横向溢出。
6. 更宽桌面继续自然扩展，不固定成窄表格。

## 中英文

- 中文和英文使用同一结构，不创建两套列表。
- 英文 `Candidate Home`、`Applied Date` 和 `Actions` 不得被挤成不可读的窄列。
- 中文标签保持自然、均衡，不因英文专用修复而出现过宽空白。
- 语言切换不得改变当前页面或功能状态。

## 测试与验收

### 自动化测试

- 先新增失败测试，证明：
  - `521px–1024px` 使用舒展两行布局；
  - `1025px` 以上恢复九列桌面表格；
  - `520px` 以下现有手机五列布局保持；
  - 桌面左右间距规则已生效。
- 保留并通过现有全部响应式、翻译、统计和表单行为测试。
- 演示版和正式版 HTML、应用脚本、逻辑脚本及 CSS 必须保持一致。

### 浏览器验收

使用中文和英文分别检查：

- `520 × 950`：手机布局不变；
- `521 × 950`：舒展两行开始生效；
- `670 × 950`：电脑半屏可读、按钮不挤；
- `821 × 950`：不再突然切换为裁切的九列表格；
- `1024 × 950`：舒展两行上边界正常；
- `1025 × 950`：九列桌面表格开始生效；
- `1200 × 900`：桌面左右间距均衡；
- `1440 × 900`：宽屏自然扩展。

每个关键视口必须满足：

- 页面无横向溢出；
- 文字、状态和按钮不重叠；
- 候选人中心、编辑、删除、筛选、排序、分组、A–Z、语言切换正常；
- 控制台无相关错误或警告。

## 发布边界

完成测试和浏览器验收后，同步演示版和正式版，再推送 GitHub Pages 并更新 Vercel。线上文件必须与本地最终文件逐字一致。整个过程不读取、修改或提交真实申请数据。
