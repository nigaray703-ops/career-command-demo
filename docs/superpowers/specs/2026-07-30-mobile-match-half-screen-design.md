# 手机端匹配电脑半屏布局设计

## 目标

让 `520px` 及以下手机界面采用已确认的电脑半屏视觉结构，同时保持首页和申请列表为两个独立页面。

用户选择的手机申请列表方案为 **B：五列缩小版**。

本轮修改同步到：

- GitHub Pages 演示源：`demo-github`
- Vercel 正式源：求职追踪器根目录

## 页面结构

### 首页

手机首页继续通过顶部导航与申请列表切换，不在同一页面混合显示申请记录。

手机首页采用与电脑半屏相同的信息层级：

1. 第一行：品牌、首页、申请列表。
2. 第二行：账号信息；下载数据、上传数据、退出登录位于账号信息下方的一行。
3. 标题、语言和添加申请保持紧凑标题区。
4. 七个指标保持 `3 + 4` 排列：
   - 第一行：总申请数、申请中、已拒。
   - 第二行：面试、Offer、拒绝率、面试率。
5. 状态分布保持圆环图在左、状态记录在右。
6. 转化率保持拒绝率和面试率并排。

### 申请列表

申请列表仍是独立页面，采用用户选择的五列缩小版：

1. 工具栏保持两行：
   - 第一行：搜索、状态筛选。
   - 第二行：排序、方向、分组。
2. 申请记录保持连续白色列表，不恢复为分离卡片。
3. 五列顺序保持：
   - 公司 / 岗位
   - 申请日期
   - 候选人中心
   - 当前状态
   - 操作
4. 列宽使用纯弹性比例，不设置会撑破手机宽度的固定最小值。
5. 公司名和岗位允许自然换行。
6. 编辑和删除保持并排，分别使用蓝色和红色描边。
7. A–Z 索引继续固定在右侧，但缩小宽度和按钮间距。

## 响应式架构

现有电脑半屏基础规则：

```css
@media (min-width: 521px) and (max-width: 820px)
```

调整为手机与半屏共享的基础结构：

```css
@media (max-width: 820px)
```

随后在文件末尾增加手机专用压缩层：

```css
@media (max-width: 520px)
```

手机压缩层只调整尺寸，不改变半屏结构：

- 减少页面、面板、单元格间距。
- 缩小圆环图、指标字号和表头字号。
- 账号区在手机上改为账号信息一行、三个账号按钮下一行。
- 五列表格改用 `fr` 比例列宽和 `minmax(0, ...)`。
- 操作按钮允许缩小但必须保持两个独立点击区域。

`821px` 及以上桌面规则保持不变。

## 数据和功能边界

以下内容不得改变：

- Supabase 配置、登录、RLS 和每账号数据隔离。
- 现有真实申请记录及字段。
- 添加、编辑、删除、导入、导出和云端同步逻辑。
- 中英文翻译。
- 搜索、状态筛选、排序、方向、分组和 A–Z 定位。
- 候选人中心链接。

仅修改 HTML 样式缓存键、CSS 和响应式测试；不修改业务逻辑。

## 窄屏处理

- 支持最小 `320px` 视口。
- 页面不得产生横向滚动。
- 五列通过弹性比例、换行和紧凑字号适配，不隐藏日期、链接、状态或操作。
- 英文长公司名、岗位名和日期允许换行，但不能覆盖相邻列。
- 操作按钮不得互相覆盖或拦截对方点击。

## 验收

### 静态测试

- 手机和电脑半屏共享 `max-width: 820px` 基础结构。
- 文件末尾存在 `max-width: 520px` 手机压缩层。
- 手机指标保持 `3 + 4` 网格。
- 手机列表保持五列连续布局。
- 样式缓存键更新为新的手机版本。

### 浏览器验收

检查以下视口：

- `320 × 844`
- `390 × 844`
- `520 × 950`
- `521 × 950`
- `670 × 950`
- `821 × 950`

验证：

- 首页和申请列表保持独立。
- 所有视口无横向页面溢出。
- `320–520px` 与电脑半屏结构一致。
- `521–820px` 现有布局没有回退。
- `821px` 桌面布局保持不变。
- 中文和英文均无文字或按钮遮挡。
- 编辑、删除、候选人中心、筛选、排序、分组和导航可用。
- 浏览器控制台错误为 `0`。
