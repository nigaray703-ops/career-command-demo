# “曾进入面试”历史里程碑与面试率设计

## 目标

让求职追踪器的面试率反映申请是否曾经进入过面试，而不是只读取当前最终状态；同时保持当前状态数量互不重复，Offer 仍然只有一个状态。

本轮修改同步到：

- GitHub Pages 演示源：`demo-github`
- Vercel 正式源：求职追踪器根目录

## 统计口径

### 当前状态数量

首页状态数字和状态分布图继续只读取每条申请的当前状态：

- “申请中”只统计当前状态为“申请中”的申请。
- “已拒”只统计当前状态为“已拒”的申请。
- “面试”只统计当前状态为“面试”的申请。
- “Offer”只统计当前状态为“Offer”的申请。
- “终面”继续作为独立当前状态显示在状态分布中。

同一条申请不会因为曾经进入面试而同时增加“面试”和“Offer”两个当前状态数字。

### 百分比

- 面试率 = `曾进入过面试的申请数 ÷ 总申请数 × 100%`。
- 拒绝率继续等于 `当前状态为已拒的申请数 ÷ 总申请数 × 100%`。
- 面试率和当前“面试”数字使用不同口径：前者是历史里程碑，后者是当前状态。

## 数据模型

每条申请增加布尔字段：

```js
everInterviewed: boolean
```

该字段表示这条申请是否曾经进入过面试阶段。

### 自动规则

- 保存当前状态为“面试”或“终面”时，`everInterviewed` 必须自动为 `true`。
- 已经为 `true` 的记录后来改成“已拒”或“Offer”时，不得自动清除。
- Offer 本身不得自动推断为曾进入面试，因为 Offer 可能没有经过面试。
- “申请中”和“已拒”本身也不得自动推断为曾进入面试。

### 手动规则

- 编辑表单增加“曾进入面试”复选项。
- 中文标签：`曾进入面试`。
- 英文标签：`Reached interview stage`。
- 当前状态为“Offer、已拒或申请中”时，用户可以手动选中或取消。
- 当前状态为“面试或终面”时，系统强制为选中状态，避免产生逻辑矛盾。
- Offer 仍然只有一个当前状态；是否经过面试仅由 `everInterviewed` 表示，不新增 Offer 来源或 Offer 子类型。

## 旧数据兼容

旧记录缺少 `everInterviewed` 字段时：

- 当前状态为“面试”或“终面”：安全自动补为 `true`。
- 当前状态为“申请中、已拒或 Offer”：补为 `false`，不猜测历史经历。
- 用户已经下载旧记录备份；已拒和 Offer 旧记录由用户打开编辑后手动补齐。

旧数据恢复、JSON 下载、JSON 上传和云端同步都必须保留该字段。云端表当前以 JSON 保存整组记录，因此不需要数据库表结构迁移。

## 表单行为

- 新增申请默认未选中“曾进入面试”。
- 当表单状态选择为“面试”或“终面”时，复选项自动选中并不可取消。
- 当表单状态为“Offer、已拒或申请中”时，复选项可由用户修改。
- 编辑已有记录时，表单显示该记录已经保存的值。
- 从“面试或终面”改到“Offer或已拒”时，原有 `true` 值继续显示为选中；用户如需纠正，可以手动取消后保存。

## 首页文案

- 当前状态卡片继续使用“面试”/`Interview`，显示当前状态为面试的数量。
- 面试率提示改为明确的历史口径：
  - 中文：`曾进入面试的申请比例`
  - 英文：`Share of applications that reached interview stage`
- Offer 卡片继续显示所有当前 Offer，不区分是否经过面试。

## 数据流

1. 读取或导入记录时，标准化 `everInterviewed`。
2. 打开编辑表单时，载入当前字段值。
3. 状态选择为面试或终面时，界面强制勾选。
4. 保存时，根据状态和复选项生成规范化记录。
5. 更新记录只覆盖当前状态和表单字段，不丢失已经保存的历史里程碑。
6. 统计时，当前状态卡片读取 `record.status`；面试率读取 `record.everInterviewed`。
7. 云端同步和备份序列化完整记录。

## 错误与边界处理

- 缺失、空值、字符串或其他非布尔值不得被随意当作 `true`。
- 只有明确的布尔值 `true`，或当前状态为面试/终面，才能产生历史面试里程碑。
- 空数据集的面试率继续为 `0`，不得除以零。
- 直接创建为 Offer 的申请默认不计入面试率，除非用户手动勾选。
- 已经面试后变成 Offer 或已拒的申请继续计入面试率，但只计入一个当前状态数量。
- 导入旧备份不得修改公司、岗位、日期、链接、备注或其他既有字段。

## 测试与验收

### 逻辑测试

- 当前为面试的记录自动得到 `everInterviewed: true`。
- 当前为终面的记录自动得到 `everInterviewed: true`。
- 直接 Offer 默认保持 `everInterviewed: false`。
- Offer 可以手动保存为 `everInterviewed: true` 或 `false`。
- “面试 → 已拒”后仍保留 `everInterviewed: true`。
- “面试 → Offer”后仍保留 `everInterviewed: true`。
- 面试数字只统计当前“面试”。
- Offer 数字只统计当前“Offer”。
- 面试率统计所有 `everInterviewed: true` 的记录。
- 空数据集面试率为 `0`。
- 旧记录和旧备份按兼容规则恢复。
- 下载、上传及序列化往返后字段不丢失。

### 浏览器验收

- 中英文编辑表单显示正确标签。
- 面试/终面状态下复选项自动选中且不能产生未面试矛盾。
- Offer、已拒和申请中状态下可以手动修改。
- 保存、重新加载和云端同步后值保持。
- 首页当前状态数字和面试率分别使用正确口径。
- 编辑既有记录不得改变无关字段。

## 隐私和发布边界

- 测试只使用虚构演示数据，不修改真实生产申请记录。
- 不修改 Supabase 登录、RLS、账号隔离或云端表权限。
- 本地验证通过后再发布 GitHub Pages 与 Vercel。
- 发布后只验证静态文件、演示数据交互和线上版本；真实账号的旧记录由用户自行补齐。
