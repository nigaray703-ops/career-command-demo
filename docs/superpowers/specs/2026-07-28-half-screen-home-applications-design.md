# 半屏首页与申请列表排版设计

## 目标

仅重新排版演示版在 `521px–820px` 宽度下的首页和申请列表，让半屏浏览时信息更紧凑、扫描更快，并减少无意义的纵向滚动。

以下范围保持不变：

- `821px` 及以上的桌面/全屏布局。
- `520px` 及以下的手机布局。
- 所有真实功能、字段、假数据、状态、链接、筛选、排序、分组、A–Z 索引、编辑和删除行为。
- 中英文翻译与现有蓝白视觉身份。

半屏首页采用以下结构：

1. 顶部第一行保留品牌、首页和申请列表导航。
2. 第二行紧凑排列 Demo User 账号信息及下载数据、上传数据、退出登录。
3. 页面标题、说明、语言选择和添加申请组成紧凑标题区。
4. 指标区保留全部七项数据：
   - 总申请数 5
   - 申请中 1
   - 已拒 1
   - 面试 1
   - Offer 1
   - 拒绝率 20%
   - 面试率 60%
5. 指标使用半屏专用紧凑网格，不能变成缩小的全屏布局。
6. 状态分布使用整行分析区，圆环图在左、五条状态记录在右。
7. 转化率使用整行区域，拒绝率和面试率并排展示。

## 申请列表

选中的视觉标准：

`/Users/nigarayaskar/.codex/generated_images/019f9ca8-6521-76a1-8fb1-503f381bd3a2/call_zr93pTmNKhsYCqep96mD0eZJ.png`

半屏申请列表采用以下结构：

1. 顶部导航、账号区和页面标题与首页使用相同的半屏节奏。
2. 工具栏分为两行：
   - 第一行：搜索与状态筛选。
   - 第二行：排序、方向、分组。
3. A–Z 索引固定在右侧，不覆盖筛选器、列表内容或操作按钮。
4. 记录不再显示为彼此分离的高卡片，而是一个连续白色列表面。
5. 每条记录使用紧凑两行信息层级：
   - 公司和岗位作为主身份信息。
   - 当前状态、申请日期、候选人中心和操作在同一记录中清晰分区。
6. 编辑按钮保留蓝色描边；删除按钮保留克制的红色描边。
7. 半屏首屏应尽量看到至少四条记录，同时确保文字和按钮不被截断。

## 技术边界

优先复用当前 HTML 表格语义和现有 JavaScript 渲染，不改变数据结构或业务逻辑。

新增的布局规则必须使用双边界媒体查询：

```css
@media (min-width: 521px) and (max-width: 820px) {
  /* 半屏专用规则 */
}
```

规则必须位于现有响应式样式之后或具备足够明确的作用域，防止影响：

- `821px` 及以上现有表格与首页。
- `520px` 及以下现有手机卡片。

若纯 CSS 无法保持所选申请列表的语义与交互，可对现有渲染标记增加最小必要类名，但不得复制数据、创建第二套列表或改变保存行为。

## 数据与错误处理

- 不增加或修改假数据。
- 空日期继续显示现有日期备注。
- 空候选人中心继续保持为空。
- 超长公司或岗位名称允许自然换行，不能撑出横向滚动。
- 中英文标签切换后不得产生遮挡或回退成中文。
- 分组行必须保持可辨识，不能继承普通申请记录的错误网格区域。
